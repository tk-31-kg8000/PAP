# README.template.md · 通用骨架说明

> **这是什么**：一套「让 Agent 能长期接手项目」的资料组织骨架，与具体项目内容无关。
>
> **怎么用**：把本仓库的全部内容复制到你的新项目目录作为**项目根**（骨架自身即项目根布局，不再套一层目录），然后按 `INIT.md` 完成初始化。填完 `README.md`（你的项目介绍）、`AGENTS.md`（运行环境与红线）即可开始工作。
>
> 本文件随骨架分发，**初始化后可删除**——它不是运行时规则的一部分，运行时规则一律以 `AGENTS.md` 为准。

---

## 一、这套骨架解决什么问题

项目资料天然分为若干类别，而它们的管理需求彼此冲突。不加区分地混放，会依次产生下列后果：

| 资料类型 | 固有特点 | 不加区分的后果 |
| --- | --- | --- |
| 代码 | 需持续演进 | 缺少版本控制则无法回溯 |
| 数据与产物 | 体积大，多数可重算 | 纳入版本控制会使仓库失效 |
| 尝试与结论 | 无天然载体 | 散落于对话、邮件与记忆中，数月后不可追溯 |
| 失败的路径 | 最易被遗忘 | 反复重试同一方案，造成重复劳动 |
| 知识 | 零散，逐步成形 | 每次都要从原始素材重新理解 |

**核心痛点**：AI Agent 每次会话都是「冷启动」。若项目没有稳定的书面约定，Agent 只能靠扫描文件猜结构、靠对话记忆猜意图，于是反复踩坑、反复追问、产出不可复现。

**本骨架的答案**：把「进入项目后读什么、写哪里、什么不能动」全部写成文件，让 Agent 无需依赖记忆即可定位一切。

## 二、目录职责

```
<项目根>/
├── README.md      项目介绍：整体框架与核心结论        ← 需要你自己填
├── STATE.md       当前进行中的各项工作，完成即移出
├── AGENTS.md      Agent 操作规则全集（唯一运行时依据）  ← 需要你自己填
├── INIT.md        初始化指南（仅初始化时读）
├── .gitignore     入库白名单：只收技术性内容
├── code/          正式源代码
├── sandbox/       试验代码，可随时丢弃
├── pending/       待定区：已保存、尚未判定用途
├── artifacts/     人产出的成品：汇报稿、论文稿、图表
├── raw/           外部输入的一手素材（只读）
├── wiki/          提炼后的知识
└── records/       决策档案：试过什么、成没成、为什么
```

各域内的 `INDEX.md` 是该域的**目录页**（回答「这里有什么」）；`sandbox/` 与 `pending/` 不设 `INDEX.md`。

## 三、设计取舍

- **以极少的目录，换取明确的归置判据。** 目录越多，归置越慢，也越容易出错。
- **「话」与「物」彻底分离。** 文字说明与文件实体归属不同区域，互不混杂。
- **只存指针，不存副本。** 引用他处内容时写路径而非复制，避免同一内容出现多个版本。
- **不搬家，就地版本化。** 旧版本留在原位，以保留演进轨迹。
- **承认「尚未判定」是合法状态**，但为其设定期限，防止堆积为无法清理的存量。
- **规则只有一处来源。** 同一条规则不在两处各写一遍，否则改一处必漏另一处。

## 四、初始化步骤

1. **复制骨架**——将本仓库**全部内容**复制到目标位置作为**项目根**；Git 仓库根同样设于此。
2. **填 `AGENTS.md`**——需要填的只有四处：项目一句话、运行环境表、本项目红线、风险区。其余骨架已完备。
3. **填 `README.md`**——项目定位、路线、已完成的工作、已得出的结论、当前进度。**以结论为主**，推导过程归 `wiki/`。
4. **填各域 `INDEX.md`**——通则见 `AGENTS.md` 的「INDEX 写法通则」，可随内容增长逐步补齐。
5. **初始化为 Git 仓库**——在项目根执行 `git init`。**`.gitignore` 必须在首次提交之前就位**。
6. **首次提交**——此后每次提交均由用户决定，AI 不自行判断。
7. **开始工作**——后续按 `AGENTS.md` 的「指令处理」表执行。

详细说明见 `INIT.md`。

## 五、规则在哪

本文件不复述规则，需要时按下表查阅——**每一处都是该项规则的唯一来源**。

| 想知道什么 | 去哪看 |
| --- | --- |
| 目录权限、内容归置、指令处理、禁止项 | `AGENTS.md` |
| INDEX 怎么写（通则） | `AGENTS.md` 的「INDEX 写法通则」 |
| INDEX 怎么写（各域特有） | 各域 `INDEX.md` 内 |
| 记录怎么写、结局词表、复核机制 | `records/INDEX.md` |
| wiki 页面怎么写 | `wiki/INDEX.md` |
| 哪些文件入库 | 仓库根 `.gitignore`（唯一事实来源） |
| 为何这样组织、如何初始化 | `INIT.md` |
