# PAP · 面向 Agent 的项目资料管理协议

**PAP**（Protocol for Agent-Participating projects）是一套**让 AI Agent 能在数十秒内接手任何项目**的资料组织协议。它不写代码，只规定一件事：项目中的每份资料各自归属何处、以什么规则读写，从而使人与 Agent 共享同一套书面约定。

---

## 一、问题与目标

**核心问题**：当前 Agent 参与项目的方式是「一次性对话」——每次会话都是冷启动，既不知道项目结构，也不记得上次的决定。这会导致三类反复出现的损耗：

| | 子问题 |
| --- | --- |
| 一 | **定位损耗**——Agent 需要重新扫描目录、猜测结构，才能找到要改的文件 |
| 二 | **决策损耗**——上一轮为什么放弃某个方案、为什么选了某条路，全部丢失 |
| 三 | **沉淀损耗**——已得出的结论散落在对话里，无法积累为可用知识 |

### 要解决的问题

1. **Agent 缺少稳定的操作依据。** 没有书面规则，Agent 只能靠猜，产出不可复现、不可审计。
2. **「话」与「物」混放。** 文字说明（结论、决策）与文件实体（代码、素材、产物）管理需求相反——前者要长期可检索，后者要体积可控——混在一起则两头都做不好。
3. **失败路径无人记录。** 最容易被遗忘的恰恰是「这条路走不通」，于是同一方案被反复重试。

---

## 二、项目路线

```
【阶段一 · 骨架定稿】
   确立目录划分与归置判据
        ↓
【阶段二 · 规则完备】
   让 AGENTS.md 自包含，覆盖权限、归置、指令处理
        ↓
【阶段三 · 实战验证】
   在真实项目中检验：Agent 能否不追问即正确落笔
```

| 阶段 | 做什么 | 解决什么 |
| --- | --- | --- |
| 一 | 划分目录、确定「话 / 物」分离的归置判据 | 定位损耗：任何资料有唯一归属 |
| 二 | 把规则写成 `AGENTS.md`，并划清各文件分工 | 决策损耗：规则显式化，不依赖记忆 |
| 三 | 在真实项目中跑通并回填 `wiki/`、`records/` | 沉淀损耗：结论与失败路径可积累 |

**为什么必须是这个顺序**：先有结构才能写规则，先有规则才能验证。若目录尚未稳定就写 `AGENTS.md`，规则会随结构调整而反复失效。

## 三、已完成的工作

### 3.1 骨架定稿

确立了以「话 / 物」为第一刀切割的目录划分：`wiki/`、`records/` 承载文字，`code/`、`artifacts/`、`raw/` 承载实体，另有 `sandbox/`（可丢弃试验）与 `pending/`（待定区）两个缓冲带。目录共 8 个，取舍是「以极少的目录换取明确的归置判据」。

### 3.2 规则自包含

`AGENTS.md` 写成为**唯一运行时依据**——Agent 只读这一个文件即可确定读取顺序、各域读写权限、内容归置规则与指令处理方式，不依赖读取其他文件。各域特有约定下沉到各自的 `INDEX.md`，做到「同一条规则只写一处」。

### 3.3 分工界定

明确划清了五类文件的分工：`README` 给定位与结论、`STATE` 给当前进展、`AGENTS` 给规则、`wiki` 给实现细节、`records` 给决策档案。并规定 `README` 与 `wiki` 的边界——**README 用于 30 秒了解项目，wiki 用于 30 分钟掌握细节**。

## 四、已得出的结论

1. **Agent 协作的前提是「不依赖记忆」。** 项目的一切约定必须落到文件里；凡是需要跨会话保持的信息，都要有唯一的书面归属。
2. **「话」与「物」必须彻底分离。** 二者的管理需求相反：话要可 diff、可检索、长期有效；物要体积可控、多数可重算。混放会使仓库失效或知识无法积累。
3. **规则只有一处来源。** 同一条规则不在两处各写一遍——否则改一处必漏另一处，且 Agent 会读到互相矛盾的两份说明。
4. **失败路径的价值不低于成功。** `records/` 记录「什么路走不通」，其作用是防止重复投入，这一点无法由版本控制或代码本身替代。
5. **「尚未判定」应被承认为合法状态，但须带期限。** 为此设 `pending/` 待定区，并要求「暂存」必须附复核日期，避免堆积成无法清理的存量。

## 七、本仓库如何复用

本仓库既是 PAP 协议自身，也可作为**任何项目**的资料骨架：

1. 复制本仓库全部内容到一个新目录，作为该项目的**项目根**；
2. 重写 `README.md` 为该项目自己的介绍；
3. 填写 `AGENTS.md` 的四处占位（项目一句话、运行环境、红线、风险区）；
4. `git init` 并确认 `.gitignore` 在首次提交前就位。

> 复制后 `README.template.md` 即可删除，其内容已由 `INIT.md` 覆盖。
