# code/ 索引

本目录存放**正式源代码**。内部按项目自身的模块划分组织，不强行套用统一结构。

> 若 `code/` 下含多个彼此独立的模型或子项目，**各成一节**，互不混排。

---

## 本索引的写法

通则见 `AGENTS.md`（「INDEX 写法通则」）。以下是本目录特有的约定。

- **按执行先后排列，不按字母序。** 入口在前，核心库居中，测试与归档在后。
- **先给执行链路，再列文件。** 让读者先看到「数据怎么走、谁调用谁」，再逐项查文件。
- **写明依赖方向。** 凡跨模块引用，注明被引用方，避免读者自行推断出错误的依赖关系。
- **归档与测试单列。** 不参与主流程的文件不与主线混排，以免被误读为必经步骤。
- **每个代码根单独一节，路径相对各自的根。** 例如 `code/A/` 与 `code/B/` 两节，表内路径分别相对 `A/`、`B/`——不是相对 `code/`。

### 每条写什么

| 列 | 写什么 |
| --- | --- |
| 文件 | 相对**该代码根**的路径 |
| 目的 | 它为什么存在——解决什么问题 |
| 作用与内容 | 它做什么、含哪些关键部分 |

**不写**函数签名、参数表、行数——这些看代码即可，写进索引只会过期。
