## 三、页面写法

每个页面统一为**「目标 + 若干环节 + 关键说明」**；每个环节内部按 **算法原理 →（专项说明）→ 代码实现** 展开。

### 页面结构

```
# 页面标题

## 目标
   本页覆盖的环节要解决什么问题，两三句。

## 一、环节名
   ### 算法原理
   ### （专项说明：关键约束 / 触发条件 / 硬约束 / 识别方式…，按需增删，非必有）
   ### 代码实现

## 二、环节名
   ### 算法原理
   ### 代码实现

## 关键说明
   ### 效果与不足
   ### 其他
```

可参照 `_页面骨架.md`（本目录内的空骨架）。

### 三点怎么写

前两点在每个环节内各写一次，第三点在页面末尾统一写一次。

| 点 | 写什么 |
| --- | --- |
| **算法原理**（环节内） | 这一步怎么算——核心公式、判断规则、推进顺序；以及**为什么这样设计**。 |
| **代码实现**（环节内） | **用什么数据结构、怎么实现的**。可贴少量关键代码。 |
| **关键说明**（页末统一） | 全页汇总，不逐环节重复。**首要是「效果与不足」**——能保证什么、保证不了什么、代价是什么。其余真正关键的点附在其后。 |

**算法原理与代码实现之间**，可视需要插入专项说明小节——例如「关键约束：……」「触发条件」「硬约束」。这类小节只在确有必要时出现，不必每处都设。

### 规则

- **不写多变的具体数值**：参数与情景是多变的，不进知识库。判据是「这个值会不会变」——多变的不写（用符号表示），固定不变的换算系数要写（如 `111320 · cos(φ)`）。
- **代码实现不写位置**：只讲数据结构与实现方式，**不写它挂在哪个文件、哪个函数**。
- **不写输入输出**：关心的是「怎么算」，不是数据是文本、数组还是别的形式。
- **不写易错点**：测试阶段踩的坑不进 wiki。
- **不写实际数据结果**：运行产物（数值、指标、图表）不进 wiki。
