# records/ 索引

本目录存放**决策档案**——不是流水日志，而是「试过什么、成没成、为什么」。

版本控制记录代码变成了什么样；这里记录**为什么**变成这样、**什么路走不通**。两者不重叠。

---

## 结构约定

- **一个月一个 `.md` 文件**，文件名即月份：`2026-09.md`
- **扁平存放，不建子目录**（不按天分文件，也不按月建文件夹）
- 当月的内容，作为一条或多条记录**追加**进当月文件
- 条目用**日期作小标题**，如 `## 2026-09-27 【尝试名】`
- 结局只用「**启用**」「**暂存**」「**丢弃**」三个固定词，便于一次性检索：

```
grep -r "结局：丢弃" .
```

---

## 记录格式

```
## 【日期】 【尝试名】

- 结局：【启用 / 暂存 / 丢弃】
- 思路：【为什么要试这个】
- 方法：【怎么做的】
- 结果：【得到了什么】
- 原因：【为什么是这个结局】
- 复核：【仅「暂存」需要填：复核日期】
- 关联：【指针：文件路径 · 提交编号 · 相关 wiki 页面】
```

### 结局只有三个词

| 结局 | 含义 | 必填字段 |
| --- | --- | --- |
| `启用` | 已移入 `code/`（产物则进 `artifacts/`） | 关联 |
| `暂存` | 已移入 `pending/` 待定区，等以后再判定 | **复核**、关联 |
| `丢弃` | 已删除 | **原因**、关联 |

**每个结局都必须先写记录、再动文件**——尤其「丢弃」：代码可以消失，但「为什么不行」必须留下。

**「暂存」必须带复核日期**（默认三个月后）。到期要做一次判定：启用 / 丢弃 / 延期。**延期最多一次**——两次都判不出来，说明它其实不重要，强制丢弃。

**只记有决策价值的事**：试过某条路并放弃、做了影响后续的选择。
日常写代码、调参数不必记——否则这个目录会变成负担，反而没人看。
